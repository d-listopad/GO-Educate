# Задача 1. Улов задаётся при запуске

## Перед задачей

Задача шага 4 влита в `main`. В терминале в корне `pond` выполнены `git switch main`
и `git pull`. Ветку для этой задачи назови `catch-on-start`.

## Контекст

Сейчас, чтобы жабка поймала другое число мух, нужно править код. Но улов каждый
раз разный, а код программы от этого меняться не должен.

## Что нужно

Сколько мух поймала жабка, задаётся при запуске программы переменной окружения
`CATCH`, без правки кода. Если улов при запуске не задан, жабка не поймала ни одной
мухи.

## Где менять

Меняются `main.go` и `README.md` в корне `pond` (не в `try`): в README появится,
как задать улов при запуске. `go.mod`, `.gitignore` и `.devcontainer` не трогаем.

Запускай программу из корня `pond`: в строке приглашения путь `/workspaces/pond`.
Если там `/workspaces/pond/try` — сначала `cd ..`.

## Критерии приёмки

- [ ] `CATCH=4 go run .` — жабка поймала 4 мухи, `CATCH=2 go run .` — 2 мухи;
      остальные числа меняются вместе с уловом. Если при `CATCH=4` мух в животе
      становится больше предела, уменьши начальное число мух первой жабки: что делать
      при переполнении — шаг 7.
- [ ] `go run .` без `CATCH` — жабка не поймала ни одной мухи, программа работает
      до конца.
- [ ] Число улова нигде не записано в коде.
- [ ] В `README.md` репозитория написано, как задать улов при запуске.
- [ ] Всё, что программа умела раньше, работает как раньше.
- [ ] `gofmt -l .` и `go vet ./...` ничего не выводят. Если `gofmt -l .` вывел файл
      из `try/` — это пример из урока: верни его в рабочее состояние и нажми в нём
      Cmd + S.
- [ ] Задача сделана в отдельной ветке и сдана через pull request с ответом на вопрос
      к разбору; после одобрения ветка влита в `main`.

## Вопрос к разбору

Что программа сообщает в каждом случае и как, по-твоему, она должна была себя вести?
