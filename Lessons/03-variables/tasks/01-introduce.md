# Задача 1. Жабка представляется

## Контекст

Пока жабка умеет только квакать. Но у неё есть имя, и она знает, сколько мух
у неё в животе. Эти сведения будут меняться: жабка будет есть, прыгать, получать
другое имя. Программа должна их где-то хранить.

## Что нужно

После кваканья жабка представляется: называет своё имя и говорит, сколько мух
у неё в животе. Имя и число мух выбери сама.

## Где менять

Меняется `main.go` в корне `pond` (не в `try`), если хочешь — `README.md`. `go.mod`,
`.gitignore` и `.devcontainer` не трогаем.

## Git: первая ветка и pull request

До сих пор коммиты сразу попадали в основную версию программы — ветку `main`.
С этой задачи работа идёт как в команде: задача делается в отдельной **ветке**
(branch), сдаётся через **pull request** — запрос на GitHub влить ветку в `main`, —
разбор проходит в нём, а после одобрения ветка вливается в `main` (**merge**).

Весь путь по шагам — в разделе Git,
[3. Ветки и pull request](../../../Git/03-branches-and-pull-requests.md). Прочитай его
до начала задачи: ветка создаётся первой, ещё до правок в коде. Ветку для этой задачи
назови `introduce-frog`.

## Критерии приёмки

- [ ] При запуске жабка представляется: в выводе есть её имя и число мух в животе.
- [ ] Имя и число мух записаны в программе каждое ровно в одном месте: чтобы поменять
      имя или число мух, достаточно исправить одну строку.
      Как проверить: поменяй имя в одной строке и запусти — новое имя должно
      появиться везде, где жабка его называет. То же с числом мух.
- [ ] Число мух хранится как целое: половины мухи не бывает.
      Как проверить: напечатай тип числа мух глаголом `%T`, например
      `fmt.Printf("%T\n", …)` с твоей переменной на месте `…`, — должно напечататься
      `int`. Убери эту строку после проверки.
- [ ] Обычное и громкое кваканье работают как раньше.
- [ ] `gofmt -l .` и `go vet ./...` ничего не выводят.
- [ ] Задача сделана в отдельной ветке и сдана через pull request. В описании pull
      request — ответ на вопрос к разбору.
- [ ] После одобрения ветка влита в `main`, а в Codespaces снова ветка `main`
      с последними изменениями.
      Как проверить: `git switch main`, `git pull`, затем `go run .` — жабка
      представляется.
