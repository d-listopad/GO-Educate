# Задача 2. Улов задаётся при запуске

## Контекст

Сейчас, чтобы жабка поймала другое число мух, нужно править код. Но улов каждый
раз разный, а код программы от этого меняться не должен.

## Что нужно

Сколько мух поймала жабка, задаётся при запуске программы переменной окружения
`CATCH`, без правки кода. Если улов при запуске не задан, жабка не поймала ни одной
мухи.

## Где менять

Меняются `main.go` и `README.md`: в README появится, как задать улов при запуске.
`go.mod` и `.devcontainer` не трогаем.

Запускай программу из корня `pond`: строка приглашения кончается на
`/workspaces/pond`. Если она кончается на `/workspaces/pond/try` — сначала `cd ..`.

## Критерии приёмки

- [ ] `CATCH=4 go run .` — жабка поймала 4 мухи, `CATCH=2 go run .` — 2 мухи;
      остальные числа меняются вместе с уловом.
- [ ] `go run .` без `CATCH` — жабка не поймала ни одной мухи, программа работает
      до конца.
- [ ] Число улова нигде не записано в коде.
- [ ] В `README.md` репозитория написано, как задать улов при запуске.
- [ ] Всё, что программа умела раньше, работает как раньше.
- [ ] `gofmt -l .` и `go vet ./...` ничего не выводят.
- [ ] Задача сделана в отдельной ветке и сдана через pull request с ответом на вопрос
      к разбору; после одобрения ветка влита в `main`.

## Вопрос к разбору

Запусти программу с `CATCH=много`, а потом с уловом больше, чем влезает в жабку.
Что программа сообщает в каждом случае и как, по-твоему, она должна была себя вести?

<summary>Подсказка</summary>

Разделы урока «Число из текста: `strconv.Atoi`» и «Значение при запуске:
`os.Getenv`».
