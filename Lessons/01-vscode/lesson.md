# Шаг 1. Редактор VS Code

## В прошлом уроке

В прошлом уроке ты создала свой репозиторий `pond`, добавила в него описание среды
`.devcontainer` и открыла Codespace. Среда настроена: `.devcontainer` и настройки
репозитория больше не меняются, а Codespace на весь курс один — его ты будешь
открывать, а не создавать заново. Но в окне Codespace много панелей и кнопок,
и пока непонятно, где что. Этот шаг — экскурсия по окну.

## Что такое редактор кода

Программа на Go — это обычный текст в файлах. Писать его можно где угодно, хоть
в «Заметках», но удобнее в программе, которая подсвечивает слова разным цветом,
показывает ошибки и сама расставляет отступы. Такая программа называется
**редактор кода** (code editor). Самый распространённый из них — **VS Code**
(Visual Studio Code).

Codespace из шага 0 — это компьютер в облаке. VS Code — его окно: через него ты
видишь файлы на этом компьютере, правишь их и даёшь компьютеру команды. Всё, что
ты делаешь в этом окне, происходит на облачном компьютере, а не на iPad.

Скриншоты в этом уроке сделаны на компьютере, у тебя окно может быть чуть другой
высоты. Красная рамка — куда смотреть или нажимать, номера расшифрованы под картинкой.

## Окно целиком

![Окно VS Code в Codespace](images/01-window.png)

*Окно Codespace, пять частей.*

1. **Activity Bar** — узкая полоска иконок слева. Переключает, что показано в панели
   справа от неё: обычно там Explorer (2), а после нажатия другой иконки — другая
   панель, например Source Control.
2. **Explorer** — панель файлов. Здесь видны все файлы и папки проекта: сейчас это
   папка `.devcontainer` и файл `README.md`. Сверху — имя проекта `pond`, а в скобках
   имя твоего Codespace. Его придумал GitHub сам, у тебя будут другие слова; по нему
   ты найдёшь Codespace в списке, когда будешь открывать его снова.
3. **Редактор** (editor) — большая область в центре. Здесь открываются файлы,
   здесь ты пишешь код. Каждый открытый файл — отдельная вкладка сверху.
4. **Panel** — нижняя панель. В ней несколько вкладок, тебе нужна одна —
   **Terminal**, о нём ниже. При первом открытии в терминале напечатано приветствие
   Codespaces, делать по нему ничего не нужно.
5. **Status Bar** — строка состояния внизу. Слева — имя Codespace, справа после
   открытия файла с кодом на Go появится версия Go. Нажимать здесь ничего не нужно.

Дальше в уроке части окна называются этими именами.

**Откуда здесь файлы.** Когда создавался Codespace, GitHub скопировал в него файлы
из репозитория `pond`. Всё, что ты меняешь в этом окне, меняется только в Codespace.
На GitHub изменения попадут, только когда ты их туда отправишь, — этому научимся
в шаге 2.

## Activity Bar: какие иконки нужны

![Иконки Activity Bar](images/02-activity-bar.png)

1. **☰** — главное меню, как меню «Файл, Правка…» в обычных программах.
2. **Explorer** — панель файлов. Если панель файлов пропала, нажми сюда.
3. **Source Control** — работа с git через кнопки. **Git** — программа, которая
   хранит историю версий файлов проекта; благодаря ей репозиторий помнит прошлые
   версии (шаг 0). В курсе git делается командами в терминале (с шага 2), эту панель
   не используем.
4. **Extensions** — дополнения редактора из шага 0, например поддержка Go. Они
   поставились сами при сборке Codespace по списку в `devcontainer.json`, здесь ничего
   не меняй.

Остальные иконки (поиск, запуск и отладка, GitHub, аккаунт, настройки, а после
открытия файла с кодом на Go — ещё колба Testing) в курсе не понадобятся.

## Файлы и папки

### Создать файл

**Куда попадёт новый файл.** В папку, которая выделена в Explorer: выделенная строка
подсвечена фоном. Если выделен файл — в ту папку, где он лежит. Самая верхняя папка
проекта, в которой лежит всё остальное, называется **корнем проекта** (project root);
у тебя это `pond`. Чтобы файл оказался в корне проекта, сначала нажми на заголовок
`pond`.

Наведи курсор на заголовок `pond` в Explorer (без трекпада — нажми на него пальцем) —
справа от него появятся четыре кнопки.

![Кнопки Explorer](images/03-explorer-buttons.png)

1. **New File...** — создать файл.
2. **New Folder...** — создать папку.

Две остальные, **Refresh** и **Collapse**, обновляют и сворачивают дерево файлов,
они не нужны.

Нажми **New File...**: в дереве появится пустое поле. Набери имя файла и нажми Enter.
Имя заканчивается **расширением** (file extension) — частью после точки, которая
говорит, что внутри файла, как `.docx` у документа Word или `.md` у `README.md`.
У файлов с кодом на Go расширение `.go`. Для пробы набери `hello.go`: это пробный файл,
в задаче шага ты его переименуешь и удалишь. Программу на Go начнём писать в шаге 2.

![Поле имени нового файла](images/04-new-file-name.png)

*Поле, в котором набирается имя нового файла.*

Файл появится в дереве (1) и сразу откроется во вкладке редактора (2).

![Новый файл открыт](images/05-file-open.png)

*1 — новый файл в Explorer, 2 — его вкладка в редакторе.*

Что ещё видно на картинке, и ничего из этого не требует действий:

- Буква **U** (untracked) рядом с файлом: git ещё не записал этот файл в историю
  версий. Сам файл в Codespace при этом сохранён — об автосохранении ниже. Записывать
  в git научимся в шаге 2.
- Цифра рядом с файлом — количество замечаний редактора: пустой файл `.go` пока
  не похож на программу.
- Синяя цифра на иконке Source Control — сколько файлов изменено.
- Серая надпись Generate code в пустом файле — подсказка, она исчезнет, как только
  начнёшь печатать.

### Создать папку

Так же, кнопкой **New Folder...**: в дереве появится поле, набери имя папки и нажми Enter.
Нажатие Escape отменяет создание.

![Поле имени новой папки](images/06-new-folder.png)

*Поле имени новой папки, в примере `demo`. Пробную папку назови как хочешь, в задаче
её нужно удалить.*

### Переименовать и удалить

Правый клик по файлу или папке в Explorer открывает меню. На iPad правый клик —
нажатие двумя пальцами на трекпаде, без трекпада — нажми на файл и подержи палец.
В меню:

- **Rename...** — имя файла превращается в поле: исправь его и нажми Enter.
- **Delete** — откроется окно с вопросом, нажми в нём **Delete**. Удалённый файл
  не вернуть.

Если меню не открывается, то же можно сделать командами в терминале: они есть
в задаче шага.

## Редактор и вкладки

Файл открывается нажатием на него в Explorer. Каждый открытый файл — вкладка сверху
редактора, между вкладками можно переключаться.

**Сохранение.** Автосохранение включено в `.devcontainer`: файл сохраняется сам через
секунду после правки, поэтому ничего не потеряется. Но когда пишешь код, нажимай
**Cmd + S**: так файл не только сохранится, но и выровняется — редактор расставит
отступы. Автосохранение этого не делает. Подробно — в шаге 2.

**Закрыть файл** — крестик на его вкладке. Файл при этом не удаляется, он только
пропадает из редактора.

![Крестик на вкладке файла](images/07-tab-close.png)

> **Не нажимай Cmd + W.** Если Codespace открыт во вкладке Safari, это сочетание
> закроет вкладку целиком, а не файл. Закрывай файл крестиком. Если вкладка всё же
> закрылась — открой Codespace снова (раздел «Как закончить занятие»), файлы на месте.

`README.md` при первом открытии показан как **[Preview] README.md** — так, как его
увидят на GitHub. В этом шаге README не правим: его ты перепишешь в задаче шага 2.

## Терминал

### Что это

Кроме кнопок, компьютеру можно давать команды текстом: набираешь строку, нажимаешь
Enter, компьютер выполняет и печатает ответ. Как переписка в чате, только собеседник —
компьютер. Окно, где идёт такая переписка, называется **терминал** (terminal),
а строка, которую ты набираешь, — **команда** (command).

Почему это нужно: запустить программу на Go, проверить её и сохранить в git можно
только командами. Кнопок для этого в курсе не будет.

### Как открыть

Терминал живёт в нижней панели, на вкладке **Terminal**. Обычно он открыт сразу.
Если нижней панели нет: главное меню **☰ → Terminal → New Terminal**.

![Меню Terminal](images/08-menu-terminal.png)

*1 — главное меню ☰, 2 — пункт Terminal, 3 — New Terminal.*

### Куда набирать

![Терминал](images/09-prompt.png)

1. Вкладка **Terminal** в нижней панели.
2. Строка приглашения (prompt). Она говорит, кто ты и где ты:
   `@логин → /workspaces/pond (main) $`.
   - `/workspaces/pond` — папка, в которой выполнится команда. Это **путь** (path):
     имена папок через косую черту, от самой верхней к нужной. На облачном компьютере
     `pond` лежит в папке `workspaces`; Explorer показывает только `pond`, поэтому
     `workspaces` ты в нём не видишь. Сейчас терминал в корне твоего проекта.
   - `main` — имя основной ветки (branch), то есть основной линии истории версий
     в git. Пока она у тебя одна, подробно — в шаге 3.
   - Знак `$` значит «жду команду».

Нажми на терминал, чтобы курсор встал после `$`, набери команду и нажми Enter.
Приглашение набирать не нужно: в уроках команды пишутся без него.

### Первая команда

Набери и нажми Enter:

```sh
go version
```

Ответ — версия Go, вида `go version go1.26.x linux/amd64`, где вместо `x` стоит цифра,
например `go1.26.9`. `linux/amd64` — система и тип процессора облачного компьютера,
запоминать не нужно.

![Ответ на go version](images/10-go-version.png)

*Команда и ответ на неё. Справа на картинке список из двух терминалов: так бывает,
если открыть New Terminal, когда терминал уже есть. Лишний закрывается иконкой корзины.*

Это и есть проверка, что Go на облачном компьютере установлен и работает.

### Если команда не заканчивается

Пока команда выполняется, новое приглашение `$` не появляется. Если команда
выполняется слишком долго или ты запустила не то — нажми **Ctrl + C**: команда
остановится, приглашение вернётся. Ctrl, а не Cmd: Cmd + C копирует выделенный текст
и команду не остановит.

**Вставить скопированную команду** — Cmd + V, как обычно. Если Safari спросит
разрешение на доступ к буферу обмена — разреши.

## Палитра команд

Всё, что умеет VS Code, можно найти по названию. Нажми **Cmd + Shift + P**: сверху
откроется поле, начинающееся с `>`. Знак `>` не стирай: с ним поле ищет команды,
без него — файлы. Набери после него часть названия — ниже появится список, выбери
нужное и нажми Enter.

![Палитра команд](images/11-palette.png)

*1 — поле палитры с набранным `Close Editor`, 2 — найденная команда. Справа от неё
показано сочетание ⌘W, но его не нажимай (см. «Редактор и вкладки»): выбирай команду
в списке.*

В курсе через палитру понадобятся:

| Команда | Что делает |
|---|---|
| **View: Close Editor** | Закрыть открытый файл, если крестик не виден |
| **Codespaces: Stop Current Codespace** | Остановить Codespace |
| **Codespaces: Rebuild Container** | Собрать облачный компьютер заново по `devcontainer.json`, как в шаге 0, если среда сломалась. Занимает несколько минут, файлы в `pond` остаются |

## Что здесь трогать не нужно

![Source Control](images/12-source-control.png)

*1 — иконка Source Control, 2 — кнопка Commit. Этой панелью в курсе не пользуемся.*

- **Source Control** и кнопка **Commit** в ней. Git в курсе — командами в терминале,
  так видно, что именно происходит. Цифра на иконке — сколько файлов изменено, она
  не требует действий.
- **Extensions.** Всё нужное установлено.
- **Chat** и подсказки вроде «Generate code» в пустом файле. Курс учит писать код
  самой.
- Всплывающие уведомления справа внизу можно закрывать крестиком. Исключение:
  уведомление от Go с предложением установить инструменты и кнопкой **Install**
  или **Install All** — нажми её, это нужно для подсказок в коде.

## Сочетания клавиш

| Сочетание | Действие |
|---|---|
| Cmd + Shift + P | Палитра команд — через неё доступно всё |
| Ctrl + ` | Показать / скрыть терминал (клавиша слева от «1») |
| Cmd + B | Показать / скрыть Explorer |
| Ctrl + C в терминале | Остановить выполняющуюся команду |

## Как закончить занятие

Codespace сам останавливается через время, которое ты задала в шаге 0
(Default idle timeout), но лучше остановить его сразу, чтобы не тратить часы. **Cmd + Shift + P**, набери `Stop Current Codespace`,
выбери **Codespaces: Stop Current Codespace**.

![Остановка Codespace](images/13-stop.png)

*Команда остановки в палитре.*

После неё на несколько секунд внизу появится уведомление об остановке, затем
останется экран с надписью **Codespace is stopped** и кнопкой **Restart codespace**.
Вкладку можно закрыть. Если нажать Restart codespace, он запустится снова.

![Codespace остановлен](images/15-stopped.png)

*Так выглядит остановленный Codespace. Кнопка Restart codespace запускает его снова.*

**Как открыть снова.** [github.com/codespaces](https://github.com/codespaces) — найди
свой Codespace в списке: его имя — те же слова, что в скобках в заголовке Explorer.
Нажми на имя. Кнопку **New codespace** на этой странице не нажимай.

![Список Codespaces](images/14-codespaces-list.png)

*1 — имя твоего Codespace, на него нажимать; под ним `твой-логин/pond`. 2 — кнопка
New codespace, её не нажимай.* Или через
репозиторий `pond`: **<> Code → Codespaces** — там уже есть твой Codespace, его нужно
открыть, а не создавать новый. Файлы, которые ты создала, остаются на месте, пока
Codespace не удалён: через 30 дней без входа (шаг 0). Сохранять работу в GitHub
научимся в шаге 2.

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Пропала панель файлов | Нажми иконку Explorer в Activity Bar или Cmd + B |
| Пропал терминал | **☰ → Terminal → New Terminal** или Ctrl + ` |
| Файл создался не в той папке | Удали его (правый клик или долгое нажатие → **Delete**), выдели нужную папку и создай файл заново |
| Нажала Cmd + W, и всё закрылось | Открой Codespace снова: «Как закончить занятие» → «Как открыть снова». Файлы на месте |
| В терминале нет `$`, команда не отвечает | Ctrl + C |
| `go: command not found` | Cmd + Shift + P → **Codespaces: Rebuild Container** |
| Внизу надпись **Restricted Mode** | Нажми на неё и выбери **Trust** |
| Экран выглядит не так, как здесь | Напиши преподавателю, что видишь, — урок поправим |
