# Задача 1. Рабочее место готово

## Что нужно

Пройти шаги ниже: завести папку для примеров из уроков и попробовать работу
с файлами.

Примеры из уроков ты будешь набирать и запускать отдельно от своей программы.
Сама программа «Пруд» с шага 2 будет лежать прямо в корне `pond`, а примеры —
в папке `try`: это черновики для пробы, в истории версий и у преподавателя должна
быть только программа.

1. **Папка.** В Explorer нажми на пустое место под списком файлов, чтобы снять
   выделение, затем **New Folder...**, набери `try` и нажми Enter. Это ты делаешь
   руками, через интерфейс.
2. **Отметка, что в `try` будет код на Go.** Её ставит команда: она создаёт в `try`
   служебный файл `go.mod`. Проверь, что в строке приглашения путь `/workspaces/pond`
   (если другой — набери `cd /workspaces/pond`), и набери по очереди, нажимая Enter
   после каждой строки:

   ```sh
   cd try
   go mod init try
   ```

   - `cd` (change directory) — перейти в папку. После неё в строке приглашения путь
     `/workspaces/pond/try`: терминал теперь в папке `try`.
   - `go mod init try`: `mod` — модуль (что это, разберём в шаге 2), `init` — «создать»,
     `try` — имя, под которым Go будет знать эти примеры; набери именно так. Команда
     ответит `go: creating new go.mod: module try` — значит, всё получилось. Файл
     `go.mod` появится в Explorer внутри `try`. Открыть и посмотреть его можно, править
     руками — нет: команды `go` записывают его в строгом виде, и ручная правка легко
     его сломает.

3. **Чтобы примеры не попали в историю версий.** Для этого в корне `pond` нужен файл
   `.gitignore` — список того, что git не записывает. Имя должно быть ровно
   `.gitignore`: git ищет файл с этим именем. Точка в начале здесь — часть имени,
   а не расширение: так называют служебные файлы, как `.devcontainer`. В Explorer
   нажми на пустое место под списком файлов, затем **New File...**, набери
   `.gitignore` и нажми Enter. В открывшийся файл напиши одну строку:

   ```
   try/
   ```

   `try/` значит «папку `try` целиком»: косая черта в конце указывает на папку.
   Файлы в `try` сохраняются в Codespace как обычно, git их только не записывает
   в историю. Поэтому `try` в Explorer станет серой — так VS Code показывает, что git
   её не записывает. Проверь, что `.gitignore` лежит в корне, рядом с `README.md`,
   а не внутри `try`.

4. **Вернуть терминал в корень.** Набери `cd ..` — две точки значат «на папку выше».
   В строке приглашения снова путь `/workspaces/pond`: в шаге 2 команды выполняются
   отсюда.

5. **Попробовать файлы.** Файл `hello.go` и папку `demo` ты создала по уроку; если нет —
   создай их в корне `pond`. Открой `hello.go`, закрой его крестиком, переименуй
   в `hi.go`, затем удали файл и папку — как в уроке. Если меню правого клика
   не открывается, то же делается командами в терминале (в корне `pond`):

   ```sh
   mv hello.go hi.go
   rm hi.go
   rm -r demo
   ```

   `mv` (move) переименовывает: старое имя, потом новое. `rm` (remove) удаляет файл,
   `rm -r` — папку со всем, что в ней. Удалённое так не вернуть, поэтому проверяй имя
   перед Enter. Если всё получилось, команды ничего не печатают: появляется новое
   приглашение, а файл в Explorer меняется или исчезает.

## Где менять

В `pond` появляются папка `try` и файл `.gitignore`. `.gitignore` больше не трогаешь.
В папку `try` дальше добавляешь примеры из уроков, а `go.mod` в ней не трогаешь.
`.devcontainer` и `README.md` не трогаем.

## Критерии приёмки

- [ ] `go version` в терминале отвечает версией Go.
- [ ] В `pond` есть папка `try`, в ней файл `go.mod`.
      Как проверить: в Explorer раскрой `try` — внутри `go.mod`.
- [ ] В корне `pond`, рядом с `README.md`, есть `.gitignore` со строкой `try/`.
- [ ] Пробный файл создан, переименован и удалён; пробная папка создана и удалена.
      Как проверить: в Explorer только `.devcontainer`, `try`, `.gitignore` и `README.md`.
- [ ] Ты знаешь, как открыть палитру команд и остановить Codespace, и остановила его
      в конце занятия.

Сохранять в git и отправлять в GitHub в этом шаге не нужно, разбора нет: это начнётся
в шаге 2. Проверь себя по критериям сама.
