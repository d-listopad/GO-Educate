# Шаг 0. Настройка среды

На iPad нельзя установить Go напрямую: iPadOS не позволяет запускать программы,
которые превращают код в работающую программу. Поэтому мы будем писать код в **GitHub
Codespaces** — это настоящий компьютер в облаке, то есть на сервере GitHub, а не на твоём
iPad. На нём стоит Linux — операционная система, как iPadOS, только для таких компьютеров.
Ты открываешь его прямо в Safari, и в нём уже есть **редактор кода** VS Code — программа,
в которой пишут код. Для учёбы это бесплатно: 60 часов в месяц.

Весь курс ты будешь делать одну программу — «Пруд». У программы много файлов: код,
описание, настройки. Все файлы одной программы, сложенные в одну папку, называют
**проектом** (project). Твой проект будет храниться на GitHub в **репозитории**
(repository) — папке на GitHub, которая помнит не только файлы, но и все их прошлые
версии. Репозиторий твоего проекта называется `pond`. А этот репозиторий, GO-Educate, —
учебник: уроки и тексты задач читаются прямо на github.com.

**GitHub Codespaces** — название сервиса, а один такой облачный компьютер называется
**Codespace**. Ты создашь один Codespace для `pond`: в нём ты будешь писать код своей
программы. Всё, что нужно для работы с кодом, — Go, редактор, его настройки — вместе
называют **средой** (environment); отсюда название шага.

Раз ты читаешь этот текст, аккаунт GitHub у тебя уже есть. Остаётся создать репозиторий,
описать в нём среду и создать Codespace — это 20–30 минут. Шаг заканчивается тем,
что Codespace открылся. Что в нём где и как с ним работать — следующий шаг.

Скриншоты сделаны в тёмной теме GitHub и на компьютере. У тебя цвета и расположение
кнопок могут немного отличаться: ищи кнопку по названию, оно выделено **жирным**.
Красной рамкой на скриншоте отмечено, куда нажимать, номера — в каком порядке.
На скриншотах логин `d-listopad` — это аккаунт преподавателя, у тебя на его месте
будет твой логин.

## Что понадобится

- iPad с клавиатурой. Трекпад или мышь очень желательны: в редакторе мелкие кнопки,
  и попадать в них пальцем неудобно.
- Safari (другие браузеры тоже подойдут, но инструкция написана под Safari).
- Держи iPad горизонтально: на узком экране GitHub прячет часть кнопок.

## 1. Свой репозиторий `pond`

1. Открой [github.com/new](https://github.com/new).
2. В поле **Repository name** набери `pond`. Под полем появится зелёное
   «pond is available» — имя свободно.
3. В **Choose visibility** выбери **Private**: репозиторий видишь только ты и те,
   кого ты пригласишь. Это учебный код, посторонним он не нужен, а доступ
   преподавателю ты дашь сама в разделе 2.
4. Включи переключатель **Add README** (положение **On**). README — файл с описанием
   проекта, GitHub показывает его на странице репозитория под списком файлов.
   Он нужен сразу, потому что Codespace нельзя создать для совсем пустого репозитория.
   Текст README ты перепишешь в задаче шага 2.
5. Остальные поля (**Description**, **Start with a template**, **Add .gitignore**,
   **Add license**) не трогай. Нажми **Create repository** внизу страницы.

![Форма создания репозитория](images/01-new-repo.png)

*1 — имя `pond`, 2 — Private, 3 — Add README включён, 4 — кнопка Create repository.*

Откроется страница твоего репозитория: имя `pond` с меткой Private и один файл
`README.md`. `.md` — расширение файла, то есть метка в конце имени, которая говорит,
что внутри; `.md` значит «текст с простой разметкой: заголовки, списки». Подробнее
о расширениях — в шаге 2.

## 2. Преподаватель — в collaborators

Collaborator — человек, которому ты дала доступ к своему репозиторию. Преподавателю
он нужен, чтобы читать твой код и оставлять замечания.

1. На странице `pond` открой **Settings**. Если вкладки не видно в строке вкладок,
   она спрятана в меню **More** справа.
2. Слева выбери **Collaborators**.
3. Нажми **Add people**, набери логин `d-listopad`, выбери его в списке под полем
   и нажми **Add to repository**.

В списке появится `d-listopad` с пометкой **Pending Invite**: приглашение ждёт, пока
преподаватель его примет. Это нормально, больше ничего делать не нужно.

![Меню More со скрытой вкладкой Settings](images/02-settings.png)

*1 — меню More, 2 — Settings.*

![Страница Collaborators](images/03-collaborators.png)

*1 — раздел Collaborators в меню слева, 2 — кнопка Add people.*

![Окно Add people](images/10-add-people.png)

*1 — поле, в котором набирается логин, 2 — кнопка Add to repository. Скриншот снят
из аккаунта самого преподавателя, поэтому под полем написано «Could not find…»:
себя пригласить нельзя. У тебя на этом месте появится строка `d-listopad`, выбери её.*

## 3. Описание среды

Codespace собирается по файлу `devcontainer.json` в папке `.devcontainer`; запись
`.devcontainer/devcontainer.json` значит то же самое: косая черта отделяет папку
от файла в ней. В этом файле сказано, какую версию Go поставить и какие дополнения
редактора включить. **Дополнение** (extension) редактора — небольшая программа, которая
добавляет ему умений, например подсветку кода на Go. Не путай со словом «расширение»
у имени файла (`.md`, `.go`): это разные вещи. Образец файла лежит в GO-Educate, его нужно
скопировать в `pond`.

1. На странице `pond` нажми **+** рядом с **Go to file** (на широком экране кнопка
   называется **Add file**) и выбери **Create new file**.

   ![Меню добавления файла](images/04-add-file.png)

   *1 — кнопка +, 2 — Create new file.*

2. В поле имени набери `.devcontainer/devcontainer.json`. После косой черты GitHub
   сам превратит `.devcontainer` в папку, и в поле останется `devcontainer.json`.
3. Скопируй содержимое образца. Открой
   [`.devcontainer/devcontainer.json`](../../.devcontainer/devcontainer.json)
   в новой вкладке: нажми на ссылку и удерживай → **Открыть в новой вкладке**, иначе
   уйдёшь со страницы, где уже набрано имя файла. На открывшейся странице нажми
   **Copy raw file** (иконка с двумя листами справа над текстом файла), вернись
   на вкладку с `pond` и вставь в большое поле редактора (Cmd + V).

   ![Кнопка Copy raw file](images/11-copy-raw.png)

   *Кнопка Copy raw file — вторая в группе справа над текстом файла, между Raw
   и кнопкой скачивания.*
4. Справа может открыться панель **Marketplace** и закрыть часть редактора. Её можно
   закрыть кнопкой с квадратиком справа от **No wrap** (рамка 4 на картинке) или
   не обращать на неё внимания. Строки мелким шрифтом под редактором — подсказки
   GitHub, на них не обращай внимания.

   ![Новый файл devcontainer.json](images/05-new-file.png)

   *1 — путь и имя файла, 2 — вставленное содержимое, 3 — кнопка Commit changes...,
   4 — кнопка, которая закрывает панель Marketplace.*

   Что ты вставила — настройки среды по строкам. Менять их не нужно:

   | Строка | Что значит |
   |---|---|
   | `"image": "…go:1.26-trixie"` | Готовая система для Codespace, в которой уже стоит Go 1.26 |
   | `"extensions": ["golang.go"]` | Дополнение редактора для Go: подсветка, подсказки, проверка кода |
   | `"editor.formatOnSave": true` | Когда сохраняешь файл сама (Cmd + S), отступы в коде расставляются сами |
   | `"files.autoSave": "afterDelay"` | Файл сохраняется сам через секунду после правки, чтобы ничего не потерялось |
   | `"cpus": 2` | Компьютер с двумя ядрами: на таком бесплатных 60 часов в месяц |
   | Остальное | Служебные строки: название среды и проверка после сборки |

5. Нажми **Commit changes...**. В открывшемся окне ничего не меняй: поле
   **Commit message** GitHub заполнил сам, выбрано **Commit directly to the main
   branch** — так и оставь. `main` — основная ветка (branch) репозитория; что такое
   ветки, разберём в шаге 3. Нажми **Commit changes**.

   ![Окно Commit changes](images/06-commit.png)

   *1 — Commit directly to the main branch, 2 — кнопка Commit changes.*

Что такое commit, разберём в шаге 2. Сейчас достаточно знать, что так файл сохраняется
в репозиторий.

## 4. Создание Codespace

1. На странице репозитория `pond` нажми зелёную кнопку **<> Code**.
2. Перейди на вкладку **Codespaces**.
3. Нажми **Create codespace on main**.

![Меню Code, вкладка Codespaces](images/07-create-codespace.png)

*1 — кнопка Code, 2 — вкладка Codespaces, 3 — Create codespace on main.*

4. Подожди. В первый раз сборка занимает 2–4 минуты: GitHub ставит в Codespace Go
   и дополнения из `devcontainer.json`. Окно редактора уже видно, но работать в нём пока нельзя:
   справа внизу висит уведомление **Setting up remote connection: Building codespace...**,
   слева внизу — **Opening Remote...**. Это нормально, дождись, пока они исчезнут.

   ![Codespace собирается](images/08-building.png)

   *Уведомление о сборке. Пока оно висит, ничего не нажимай.*

5. Появится окно **Do you trust the authors of the files in this folder?** — «доверяешь
   ли ты авторам файлов в этой папке». Это твой репозиторий, нажми
   **Trust Folder & Continue**. Без этого Codespace останется в ограниченном режиме
   (Restricted Mode) и не даст запускать программы.
6. Справа может быть открыта панель **Chat** — помощник с искусственным интеллектом,
   который пишет код за тебя. В курсе код пишешь ты сама, иначе не научишься, поэтому
   закрой панель крестиком в правом верхнем углу. Если она откроется снова — закрой
   так же.

![Окно доверия папке и панель Chat](images/09-trust.png)

*1 — Trust Folder & Continue, 2 — крестик, который закрывает панель Chat.*

Codespace готов. Что в этом окне где — в шаге 1.

## 5. Настройка Safari на iPad

**Весь экран под Safari.** Если рядом с Safari открыто другое приложение, закрой его:
редактору нужна вся ширина экрана.

**Отдельное окно без вкладок.** Когда Codespace открыт, нажми в Safari кнопку
**Поделиться** (квадрат со стрелкой вверх) → **На экран «Домой»**. На экране «Домой»
появится иконка Codespace, дальше открывай его через неё. Зачем: в обычном Safari
некоторые сочетания клавиш срабатывают в браузере, а не в редакторе, — например,
Cmd + W закрывает вкладку Safari целиком. В отдельном окне сочетания работают как
в редакторе.

**Раскладка.** Код пишется в английской раскладке: слова Go пишутся латиницей,
а фигурные скобки `{}` есть только в английской раскладке. Переключение — клавиша с глобусом
или Ctrl + Пробел, в зависимости от клавиатуры.

## 6. Лимиты Codespaces

| Ресурс | Лимит |
|---|---|
| Время работы | 60 часов в месяц на 2-ядерной машине |
| Хранилище | 15 ГБ |
| Хранение остановленного Codespace | 30 дней без активности, потом удаление |

Часы списываются с **твоего** аккаунта. Посмотреть остаток можно в настройках
аккаунта — это не те Settings, что у репозитория в разделе 2. Нажми на свою аватарку
справа вверху на любой странице GitHub → **Settings**, затем слева
**Billing and plans → Plans and usage**, раздел **Codespaces**.

![Меню аватарки](images/12-avatar-menu.png)

*1 — аватарка, 2 — Settings: настройки аккаунта. Серым закрыто имя владельца
скриншота, у тебя там будет твоё.*

**Чтобы часы не утекали:**

- Не создавай несколько Codespace для одного репозитория. Нужен ровно один, и потом
  ты всегда открываешь его, а не создаёшь новый. Как открыть существующий — в шаге 1;
  кнопку **Create codespace on main** больше не нажимай.
- Уменьши время до автоостановки. Codespace сам останавливается, если в нём ничего
  не делать, по умолчанию через 30 минут, и всё это время часы списываются. В настройках
  аккаунта (аватарка → **Settings**) слева выбери **Codespaces** и в **Default idle
  timeout** поставь 15 минут и нажми **Save** справа от поля: если забудешь
  остановить Codespace, потеряешь меньше.

  ![Default idle timeout](images/13-idle-timeout.png)

  *Поле Default idle timeout, по умолчанию 30 minutes. Остальные настройки на этой
  странице не трогай.*
- Закончила заниматься — останови Codespace. Как — в шаге 1.

Codespace — временная машина: если не заходить в него 30 дней, GitHub удалит его вместе
со всеми файлами, которые не были отправлены в репозиторий. Как сохранять работу
в репозиторий, курс покажет в шаге 2.

## Что настроено и что меняется

После этого шага часть проекта настроена раз и навсегда, а часть будет меняться
в каждой задаче. Таблица дополняется по ходу курса. Строки с шагом больше 0 — файлы,
которых у тебя пока нет: они появятся в указанном шаге, создавать их сейчас не нужно.

| Что | С какого шага | Трогать? |
|---|---|---|
| `.devcontainer/devcontainer.json` | 0 | Нет. Если среда сломалась — Rebuild Container (шаг 1), а не правка файла |
| Codespace | 0 | Один на весь курс. Открывать существующий, не создавать новый |
| Collaborators в Settings | 0 | Нет |
| `README.md` | 0 | Сейчас нет. С шага 2 — да, когда программа научилась новому |
| Папка `try` и `.gitignore` | 1 | `try` — да, здесь примеры из уроков. `.gitignore` — нет |
| `go.mod` | 2 | Руками нет. Его меняют только команды `go` |
| `main.go` | 2 | Да, здесь пишется программа |

## Как проходить урок

Каждый следующий шаг курса проходится в одном и том же порядке. Шаг — это 10–20 минут
чтения и 1–2 часа практики, его не нужно делать за один раз.

1. **Прочитать урок** в GO-Educate: `Lessons/NN-tema/lesson.md`, где `NN-tema` —
   номер шага и тема, например `Lessons/01-vscode/lesson.md`. Незнакомое слово —
   в [словаре терминов](../glossary.md).
2. **Набрать примеры руками** в Codespace и запустить их. Не копировать: когда код
   набираешь сама, запоминается синтаксис — правила записи кода: где скобки, где
   кавычки, где точка, а опечатки сразу показывают, как выглядят
   ошибки. Для примеров есть отдельная папка `try`, её ты заведёшь в задаче шага 1.
3. **Ответить на «Проверь себя»** в конце урока. Сначала ответ своими словами, потом
   раскрыть правильный. Если ответ не совпал — перечитать нужный раздел, прежде чем
   идти дальше.
4. **Сделать задачи** из папки `tasks/` рядом с уроком — в своём репозитории `pond`,
   по порядку номеров. В каждой задаче раздел «Где менять» говорит, какие файлы
   она меняет, а какие трогать не нужно.
5. **Проверить себя по критериям приёмки.** Каждый пункт с флажком должен выполняться.
   Флажки — список для самопроверки: на GitHub они не нажимаются, отмечать ничего
   не нужно.
   Если под пунктом написано «Как проверить» — сделать именно эту проверку.
6. **Сохранить работу и отправить в GitHub.** Как это делается, покажет задача шага 2,
   а подробно — раздел [Git](../../Git/README.md).
7. **Пройти разбор**: преподаватель оставит замечания на GitHub, ты отвечаешь на них
   и исправляешь код. Где их найти и как сообщить, что задача готова, покажут задача
   шага 2 и, с шага 3, pull request.

**Если застряла:**

- Прочитать сообщение об ошибке целиком: в нём файл, строка и что не так.
- Найти сообщение в таблице «Типичные ошибки» урока.
- Вернуться к разделу урока, на который ссылается подсказка в задаче.
- Не получилось за 20–30 минут — записать, что пробовала, и спросить преподавателя.
  Это нормальная часть работы, а не провал.

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Нет вкладки Codespaces в меню Code | Проверь, что ты вошла в свой аккаунт GitHub |
| Нет вкладки Settings | Она в меню **More** в строке вкладок репозитория |
| Нет кнопки Add file | На узком экране вместо неё кнопка **+** рядом с Go to file |
| Сборка висит больше 5 минут | Обнови страницу |
| Нажала Cancel в окне доверия | Внизу окна будет надпись **Restricted Mode**. Нажми на неё и выбери **Trust** |
| Экран выглядит не так, как описано здесь | GitHub иногда меняет интерфейс. Напиши преподавателю, что видишь, — урок поправим |
| Закончились 60 часов | Ждать начала следующего месяца или спросить у преподавателя про запасной вариант |
