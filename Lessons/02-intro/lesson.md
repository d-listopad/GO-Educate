# Шаг 2. Предисловие: файл, пакет и программа на Go

## В прошлом уроке

В прошлом уроке мы разобрали окно VS Code: Explorer, редактор и терминал. Среда
больше не меняется. Теперь `pond` становится проектом на Go с первой программой.

## Чему мы научимся

- Создавать проект на Go и понимать, из каких он файлов.
- Читать строки `package main`, `import "fmt"` и `func main()`.
- Запускать программу и читать сообщения об ошибках.
- Проверять код командами `gofmt` и `go vet`.

С этих строк начинается каждый файл на Go.

## Где применяется. Как часто используется

`package` и `import` — в каждом файле `.go`, `func main` и `go.mod` — по одному
на программу, `go run` — десятки раз в день.

## Объяснение материала

### Проект на Go

Проект на Go — папка с файлами `.go` и `go.mod`. После раздела `pond` будет таким:

```
pond/
  .devcontainer/   — описание среды
  README.md
  go.mod           — файл модуля
  main.go          — код программы
```

| Что | Как появляется | Можно ли назвать иначе |
|---|---|---|
| `.devcontainer/`, `README.md` | Уже есть, с шага 0 | — |
| `go.mod` | Создаёт команда `go mod init`. Руками не правится | Нет |
| `main.go` | Создаёшь ты кнопкой **New File...** | Можно, но принято `main.go` |

**1. `go.mod`.** В терминале в `/workspaces/pond` набери:

```
$ go mod init pond
go: creating new go.mod: module pond
```

`$` — приглашение (шаг 1), его не набирай; строкой ниже — ответ. `mod` — модуль,
`init` — «создай», `pond` — имя модуля. В Explorer появится `go.mod`:

`go.mod`
```
module pond

go 1.26.9
```

![Файл go.mod в редакторе](images/03-go-mod.png)

*1 — имя модуля, 2 — версия Go (последняя цифра может отличаться). Мелкую строку
над ними рисует редактор.*

**Модуль** (module) — так Go называет проект; он начинается там, где лежит `go.mod`.

**2. `main.go`.** В Explorer нажми на пустое место под файлами, затем **New File...**
(шаг 1). Набери программу и нажми **Cmd + S**:

`main.go`
```go
package main

import "fmt"

func main() {
	fmt.Println("Привет, Go!")
}
```

**3. Запуск.** В терминале, в корне `pond`:

```
$ go run .
Привет, Go!
```

![Первая программа в редакторе и её запуск в терминале](images/01-program.png)

*1 — программа, 2 — команда запуска, 3 — вывод. Номера строк слева и пунктир
под `"fmt"` рисует редактор; буква U у файла — о ней позже.*

Точка — «текущая папка». Компьютер не понимает человеческих слов, он работает
с нулями и единицами. Программу переводит программа-переводчик — **компилятор**
(compiler), его запускает `go run`. Компилятор читает весь код до запуска, поэтому
ошибки видны сразу.

### Функция

**Функция** (function) — несколько действий под одним именем. Выполнить её по имени —
**вызов функции** (function call).

![Объявление и вызов функции в первой программе](images/04-function.png)

*1 — объявление `main`, 2 — вызов `Println`.*

- `func main() { ... }` (1) — **объявление**: `func`, имя, скобки, а между `{` и `}`
  действия.
- `fmt.Println("Привет, Go!")` (2) — **вызов**: имя, в скобках то, что передают.
  `Println` (Print line) печатает переданное и переводит строку.

### Пакет `main` и функция `main`

![package main и func main в первой программе](images/05-package-main.png)

*1 — строка `package main`, 2 — функция `main`.*

**Пакет** (package) — файлы `.go` одной папки с одинаковой первой строкой
`package имя` (1). Имя пакета — из этой строки, а не из имени папки: папка `pond`,
пакет `main`. Запустить можно только пакет `main`, выполнение начинается с его
функции `main` (2).

### `import`: подключение пакета

![import и вызов функции из пакета](images/06-import.png)

*1 — подключение `fmt`, 2 — имя пакета, 3 — функция из него.*

`Println` лежит в пакете `fmt` из **стандартной библиотеки** (standard library) —
пакетов, поставляемых с Go. Пакет подключают строкой `import "fmt"` (1), функции
вызывают через имя пакета и точку (2, 3).

Снаружи пакета видны только имена с заглавной буквы — **экспортируемые** (exported):
`fmt.println` нет. Остальное — внутреннее устройство пакета, оно меняется
в обновлениях, а экспортируемые имена обещают не менять.

Неиспользованный импорт — ошибка: Go не даёт копиться мусору. **Cmd + S** сам убирает
лишние `import`, дописывает нужные и расставляет отступы (автосохранение — нет).

Текст в кавычках — **строковый литерал** (string literal): Go печатает его как есть,
он может быть любым.

### Проверка и чтение ошибок

Обе команды — в корне `pond`:

- `gofmt -l .` — перечисляет (`-l`, list) файлы, где отступы не по правилам Go.
  Вывела имя — открой файл и нажми Cmd + S.
- `go vet ./...` — ищет код, который компилируется, но почти наверняка ошибочен.
  `./...` — эта папка и все внутри.

Молчат обе — всё в порядке; их запускают перед каждым коммитом. Ошибку компилятор
показывает с местом, например `fmt.println`:

```
$ go run .
# pond
./main.go:6:6: undefined: fmt.println (but have Println)
```

![Ошибка компилятора в редакторе и терминале](images/08-error.png)

*1 — ошибка в коде, 2 — модуль, 3 — файл, строка, столбец (символ в строке)
и описание.*

Исправляй первую ошибку и запускай снова: следующие часто её следствие.

### Как принято в Go

Стиль задаёт `gofmt`, один для всех.

### Типичные ошибки

| Сообщение | Причина |
|---|---|
| `undefined: fmt.println (but have Println)` | Имя со строчной буквы снаружи не видно |
| `"fmt" imported and not used` | Пакет подключён, но не используется |
| `syntax error: unexpected EOF, expected }` | Нет закрывающей `}`; EOF — конец файла |
| `package pond is not a main package` | Первая строка — не `package main` |

### Проверь себя

«Сломай» — в `main.go`. После ответа верни как было (Cmd + Z) и проверь: `go run .`
снова печатает `Привет, Go!`.

1. Что напечатает эта программа?

   ```go
   package main

   import "fmt"

   func main() {
   	fmt.Println("раз")
   	fmt.Println("два")
   }
   ```

   <details>
   <summary>Ответ</summary>

   `раз`, затем `два` на новой строке: действия выполняются сверху вниз.

   </details>

2. Сломай: удали последнюю `}`. Что скажет компилятор?

   <details>
   <summary>Ответ</summary>

   `syntax error: unexpected EOF, expected }`.

   </details>

3. Сломай: напиши `fmt.println`. Почему так нельзя?

   <details>
   <summary>Ответ</summary>

   `undefined: fmt.println (but have Println)`: имя не экспортируемое.

   </details>
