# Задача 2. Жабку слышно с другого берега

## Контекст

Жабка квакает, но тихо: с другого берега пруда её не слышно.

## Что нужно

После обычного кваканья жабка квакает ещё раз — громко, то есть заглавными буквами.

## Где менять

Меняется `main.go`. `go.mod` и `.devcontainer` не трогаем.

## Git: что изменилось

Перед коммитом посмотри, что именно войдёт в него: `git status` покажет изменённые
файлы, `git diff` — изменённые строки. Набирай `git diff` до `git add .`: после отметки
он ничего не покажет. Все команды — в корне `pond`. После коммита `git log --oneline` покажет
историю проекта. Подробно — в разделе Git,
[1. Репозиторий и коммит](../../../Git/01-repository-and-commit.md).

## Критерии приёмки

- [ ] При запуске жабка квакает дважды: сначала обычно, потом громко.
- [ ] Громкий вариант получен из обычного готовой функцией стандартной библиотеки,
      а не набран вручную.
      Как проверить: найди в коде громкое кваканье заглавными буквами — его там
      быть не должно, заглавные буквы появляются только при запуске.
- [ ] Обычное кваканье работает как раньше.
- [ ] `gofmt -l .` и `go vet ./...` ничего не выводят.
- [ ] Работа сохранена коммитом и отправлена в GitHub (push). Сообщение коммита
      говорит, что сделано.
      Как проверить: `git log --oneline` показывает сверху два твоих коммита — новый
      и из задачи 1, по сообщениям понятно, что изменилось в каждом. Ниже — два
      коммита из шага 0 (Initial commit и Create devcontainer.json): их создал GitHub,
      когда ты создавала репозиторий и файл.

## Вопрос к разбору

Почему громкий вариант лучше получать функцией из обычного, а не набирать заглавными
вручную?

Ответ напиши комментарием к своему коммиту на GitHub (раздел Git,
[2. GitHub: push и pull](../../../Git/02-github-push-pull.md), «Комментарии к коммиту»).

<details>
<summary>Подсказка</summary>

Нужная функция есть в таблице раздела урока «Стандартная библиотека», как подключить

если жабка заквакает по-другому.
