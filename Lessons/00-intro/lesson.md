# Шаг 0. Предисловие: файл, пакет и программа на Go

## Чему мы научимся

- Читать любой файл на Go: понимать, что означают строки `package main`,
  `import "fmt"` и `func main()`.
- Объяснять, что такое пакет (package) и почему он служит пространством имён (namespace).
- Подключать пакеты стандартной библиотеки через `import` и находить в них нужные функции.
- Запускать программу командой `go run` и форматировать код командой `go fmt`.
- Читать сообщения компилятора и находить по ним место ошибки.

Для чего это нужно знать: каждый файл на Go начинается с одних и тех же строк, и каждый
пример — в этом курсе, в A Tour of Go, в документации — построен по одной схеме.
Пока эти строки непонятны, любой пример выглядит как заклинание, которое надо повторять
без изменений. Этот шаг почти не добавляет новых возможностей языка, но делает все
последующие примеры читаемыми и позволяет учиться по первоисточникам.

## Где применяется. Как часто используется

- `package` — первая строка каждого файла `.go`, без исключений.
- `import` — почти в каждом файле. Файл без импортов встречается редко.
- `func main` — ровно один раз на программу. У библиотек его нет.
- Обращение к чужой функции через имя пакета — в каждой строке такого вызова:
  `fmt.Println`, `strings.ToUpper`, `time.Now`.
- `go run` и `go fmt` — ежедневные команды. В Codespaces форматирование выполняется
  при каждом сохранении файла, поэтому вручную его вызывают редко.

Это повседневный материал: без него не пишется и не читается ни одна программа на Go.

## Объяснение материала

### Как устроена разработка на Go

Исходный код (source code) — текстовые файлы с расширением `.go`. Компилятор (compiler)
переводит исходный код в исполняемый файл, который операционная система может запустить.
В Go компилятор и остальные инструменты объединены в одну команду `go`.

Go — компилируемый язык (compiled language). Перед запуском компилятор проверяет весь код
целиком, и если в нём есть ошибка, программа не собирается вовсе. В интерпретируемых
языках (interpreted languages) ошибка проявляется только тогда, когда выполнение доходит
до неверной строки. В Go она видна сразу, до первого запуска.

Код организован на трёх уровнях:

| Уровень | Что это | Чем задаётся |
|---|---|---|
| Модуль (module) | Весь проект целиком | Файл `go.mod` в корне репозитория |
| Пакет (package) | Папка с файлами `.go` | Строка `package имя` в начале каждого файла |
| Файл (file) | Единица текста | Имя файла с расширением `.go` |

Файл `go.mod` в этом репозитории уже создан. Пока достаточно знать: он отмечает корень
проекта и называет модуль `go-educate`. Его устройство разбирается в шаге 11.

### Пакет и пространство имён

**Пакет** (package) — набор файлов `.go`, лежащих в одной папке и начинающихся
с одинаковой строки `package имя`. Компилятор обрабатывает пакет целиком: все файлы
одного пакета видят имена друг друга без каких-либо объявлений.

**Пространство имён** (namespace) — область, внутри которой каждое имя уникально
и означает ровно одну вещь. В Go пространством имён служит пакет. Внутри одного пакета
не может быть двух функций `Parse`, а в разных пакетах — может. Обращение к имени
из другого пакета всегда записывается через точку: `пакет.Имя`.

Зачем это нужно на практике. В стандартной библиотеке есть функция `time.Parse`,
которая разбирает дату из строки, функция `url.Parse`, которая разбирает веб-адрес,
и функция `strconv.ParseInt`, которая разбирает целое число. Имя `Parse` у них общее,
потому что каждая живёт в своём пакете, и читатель по префиксу сразу видит, какая именно
имеется в виду. Без пространств имён авторам пришлось бы придумывать `ParseTime`,
`ParseURL`, `ParseInt` и следить, чтобы имена не совпали ни с чем во всей программе.

В реальном проекте код делят на пакеты по ответственности: `config` читает настройки,
`storage` сохраняет данные, `report` строит отчёты. Тогда вызов читается как фраза:
`config.Load()` — «из конфигурации загрузить», `storage.Save(...)` — «в хранилище
сохранить». Имя пакета говорит, откуда функция и за что она отвечает.

**Экспортируемые имена** (exported names). Из пакета наружу видны только имена,
начинающиеся с заглавной буквы. `fmt.Println` существует, а `fmt.println` — нет.
Имена со строчной буквы доступны только внутри своего пакета. Это единственный механизм
видимости в Go: нет ключевых слов вроде `public` и `private`. Подробно — в шаге 6.

**Пакет `main`** — особый. Только из него компилятор собирает исполняемую программу,
и в нём обязательно должна быть функция `main` — точка входа (entry point), с которой
начинается выполнение. Все остальные пакеты — библиотеки (library): наборы функций,
которыми пользуются другие пакеты. Запустить библиотеку саму по себе нельзя.
До шага 6 весь код курса находится в пакете `main`.

### Объявление `import`

**Объявление `import`** делает экспортируемые имена другого пакета доступными
в текущем файле. После ключевого слова указывается путь импорта (import path)
в двойных кавычках. Имя, через которое затем обращаются к пакету, — последний элемент
пути: после `import "math/rand"` пишут `rand.Intn(10)`.

Один пакет:

```go
import "fmt"
```

Несколько пакетов записываются группой в круглых скобках, по одному в строке:

```go
import (
	"fmt"
	"strings"
)
```

Два правила, которые проверяет компилятор:

- Импорт действует в пределах файла, а не пакета. Каждый файл подключает то,
  что использует сам.
- Подключённый, но не использованный пакет — ошибка компиляции, а не предупреждение.
  Программа с лишним импортом не соберётся.

Расширение Go в Codespaces при сохранении файла само добавляет недостающие импорты
и удаляет лишние. Поэтому на практике блок `import` чаще читают, чем пишут руками.

### Стандартная библиотека

**Стандартная библиотека** (standard library) — пакеты, которые поставляются вместе с Go.
Они подключаются по короткому пути и не требуют установки. Самые частые из простых:

| Пакет | Назначение | Пример |
|---|---|---|
| `fmt` | Вывод на экран и форматирование | `fmt.Println("текст")` |
| `strings` | Операции над строками | `strings.ToUpper("go")` → `"GO"` |
| `strconv` | Преобразование строк в числа и обратно | `strconv.Itoa(42)` → `"42"` |
| `math` | Математические функции и константы | `math.Sqrt(16)` → `4` |
| `math/rand` | Случайные числа | `rand.Intn(10)` |
| `os` | Работа с операционной системой: файлы, аргументы | `os.ReadFile("a.txt")` |
| `time` | Время и даты | `time.Now()` |
| `errors` | Создание и проверка ошибок | `errors.New("текст")` |

Полный каталог — на [pkg.go.dev/std](https://pkg.go.dev/std). Описание любой функции
можно получить и без браузера, в терминале:

```sh
go doc fmt.Println
```

Команда печатает сигнатуру функции и её описание из документации.

### Разбор файла

`main.go`
```go
package main

import "fmt"

func main() {
	fmt.Println("Привет, Go!")
}
```

| Строка | Код | Значение |
|---|---|---|
| 1 | `package main` | Файл принадлежит пакету `main`: это программа, а не библиотека |
| 3 | `import "fmt"` | Подключён пакет `fmt` из стандартной библиотеки |
| 5 | `func main() {` | Объявление функции `main` — точки входа. Выполнение начинается с первой строки её тела |
| 6 | `fmt.Println("Привет, Go!")` | Вызов функции `Println` из пакета `fmt`: печатает аргументы и переводит строку |
| 7 | `}` | Конец тела функции |

Текст в двойных кавычках — строковый литерал (string literal), то есть строка, записанная
прямо в коде. Отступ в строке 6 — один символ табуляции; его ставит форматировщик.
Пустые строки 2 и 4 разделяют части файла, форматировщик их сохраняет.

Что такое функция в общем виде, разбирается в шаге 3. Пока `func main() { ... }` —
обязательная рамка, внутри которой пишется весь код программы.

Файлы в A Tour of Go устроены так же. Между `import` и `func main` там могут стоять
объявления на уровне пакета, например строки, начинающиеся с `var`. О них — в шаге 1.

### Запуск и форматирование

Команда запуска выполняется в терминале из папки, где лежит файл:

```sh
go run .
```

Точка означает «текущая папка». Команда компилирует пакет `main` из этой папки
и сразу запускает результат. Исполняемый файл на диске при этом не остаётся.
Можно указать и конкретный файл: `go run main.go`.

Команда `go build` компилирует программу в исполняемый файл и не запускает его.
В курсе она не понадобится: для проверки достаточно `go run`, а для заданий — `go test`.

**Форматировщик** (formatter) `gofmt` приводит код к единому стилю: отступы, пробелы,
переносы, порядок импортов. В Codespaces он срабатывает при каждом сохранении.
Из терминала весь проект форматируется командой `go fmt ./...`, а команда `gofmt -l .`
только перечисляет файлы, которые отформатированы неверно, ничего не меняя.

**Сообщения компилятора** имеют единый формат:

```
main.go:6:6: undefined: fmt.println (but have Println)
```

Четыре части через двоеточие: имя файла, номер строки, номер столбца, описание.
Строка и столбец указывают на место, где компилятор обнаружил проблему. Иногда сама
причина находится строкой выше, например незакрытая скобка.

Порядок чтения: исправлять первую ошибку и запускать снова. Последующие ошибки часто
оказываются следствием первой. Синтаксические ошибки (syntax error) компилятор показывает
раньше остальных: пока файл не разбирается, другие проверки не выполняются.

### Как принято в Go

**Форматирование не обсуждается.** Стиль задаёт `gofmt`, и он один для всех проектов
в мире. Код незнакомого автора выглядит так же, как свой. В сообществе это выражено
пословицей: «стиль gofmt никому не любимый, но gofmt любят все». В курсе форматирование
никогда не будет темой обсуждения: его делает инструмент.

**Компилятор строг намеренно.** Неиспользованный импорт — ошибка, а не предупреждение.
Так же будет и с неиспользованными переменными в шаге 1. Логика: неиспользуемый код —
либо ошибка, либо мусор, и Go не позволяет ему накапливаться.

**Имя пакета пишется в каждом вызове.** `fmt.Println`, а не `Println`. В Go нет
общепринятого способа подключить все имена пакета без префикса, и это считается
достоинством: читатель всегда видит, откуда взята функция, не поднимаясь к импортам.

**Одна папка — один пакет.** Все файлы в папке принадлежат одному пакету. Имена файлов
пишутся строчными буквами, файл с функцией `main` принято называть `main.go`.

### Типичные ошибки

| Сообщение | Причина | Исправление |
|---|---|---|
| `undefined: fmt.println (but have Println)` | Имя написано со строчной буквы. Экспортируемые имена начинаются с заглавной | Исправить регистр: `fmt.Println` |
| `"strings" imported and not used` | Пакет подключён, но ни одна его функция не вызвана | Удалить строку импорта или использовать пакет |
| `syntax error: unexpected EOF, expected }` | Не хватает закрывающей фигурной скобки. EOF — конец файла: компилятор дошёл до конца, а `}` не встретил | Добавить `}` |
| `function main is undeclared in the main package` | В пакете `main` нет функции `main` | Добавить `func main() { ... }` |
| `package ... is not a main package` | Первая строка файла — не `package main`. Команда `go run` запускает только программы | Заменить имя пакета на `main` |
