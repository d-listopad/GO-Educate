# Задача 1. У программы «Пруд» появляется дом

## Контекст

Весь курс ты делаешь одно приложение — «Пруд», консольную программу о жабках.
Каждая следующая задача будет добавлять ему новую возможность, и к концу курса
получится рабочая программа. Сегодня у неё появляется собственный репозиторий,
а жабка в первый раз подаёт голос.

## Что нужно

Завести проект и сделать так, чтобы при запуске программы жабка квакала.

Как создать репозиторий и Codespace для него, описано в гайде
[Подготовка среды разработки](../../../Introduction/Prepare-development-environment.md).

Проект — Go-модуль. Модуль создаётся одной командой в корне репозитория:

```sh
go mod init github.com/<твой-логин-на-GitHub>/pond
```

Пока это ритуал: команда создаёт файл `go.mod`, который отмечает корень проекта
и даёт ему имя. Что в нём написано и зачем — в шаге 11.

### Структура проекта

Так проект должен выглядеть после этой задачи. Эту структуру мы будем развивать
весь курс, поэтому важно начать с правильной.

```
pond/
  .devcontainer/
    devcontainer.json   — описание среды, копия из GO-Educate
  go.mod                — создан командой go mod init
  main.go               — package main и функция main: отсюда программа запускается
  README.md             — что это за программа и как её запустить
```

Всё лежит в корне репозитория, без дополнительных папок. Когда программа вырастет,
у неё появятся свои пакеты; где они будут лежать, мы разберём в шаге 6.

## Критерии приёмки

- [ ] Репозиторий `pond` создан в твоём аккаунте GitHub, он приватный, преподаватель
      добавлен в collaborators.
- [ ] Структура проекта совпадает с описанной выше.
- [ ] `go run .` в корне репозитория запускает программу, и жабка квакает.
- [ ] В `README.md` одна-две фразы: что это за программа и какой командой её запустить.
- [ ] `gofmt -l .` и `go vet ./...` ничего не выводят.
- [ ] Работа закоммичена и отправлена в GitHub. Сообщение коммита говорит, что сделано.
