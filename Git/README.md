# Git

Git хранит историю кода. В курсе через него сдаётся каждая задача.

| Часть | Что внутри | Когда читать |
|---|---|---|
| [1. Репозиторий и коммит](01-repository-and-commit.md) | Репозиторий, коммит; `git status`, `git diff`, `git add`, `git commit`, `git log` | Шаг 2, задача 1 |
| [2. GitHub: push и pull](02-github-push-pull.md) | Отправить коммиты в GitHub и забрать оттуда | Шаг 2, задача 1 |
| [3. Ветки и pull request](03-branches-and-pull-requests.md) | Ветка, pull request, разбор, слияние | Когда задача попросит pull request |

Термины остаются английскими (commit, push, pull, branch, merge): по ним ищут
в документации. Жаргон вроде «закоммитить», «запушить» не используем — пишем, что
делаем: «сохранить коммитом», «отправить в GitHub (push)».

## Шпаргалка

| Команда | Что делает |
|---|---|
| `git status` | Какие файлы изменены и что войдёт в коммит |
| `git diff` | Изменения построчно |
| `git add .` | Отметить все изменения для коммита |
| `git commit -m "сообщение"` | Сохранить отмеченное коммитом |
| `git log --oneline` | История коммитов, по строке на коммит |
| `git push` | Отправить новые коммиты в GitHub |
| `git pull` | Забрать новые коммиты из GitHub |
| `git switch -c имя` | Создать ветку и перейти в неё (ветки — позже) |
| `git switch main` | Вернуться в ветку `main` (позже) |
