# Git

Git хранит историю кода. В курсе через него сдаётся каждая задача: ты сохраняешь
работу коммитом и отправляешь на GitHub, где её видит преподаватель. Раздел из трёх
частей, каждую читаешь, когда до неё дойдёт задача.

| Часть | Что внутри | Когда читать |
|---|---|---|
| [1. Репозиторий и коммит](01-repository-and-commit.md) | Репозиторий, коммит; `git status`, `git diff`, `git add`, `git commit`, `git log` | Когда задача попросит коммит |
| [2. GitHub: push и pull](02-github-push-pull.md) | Отправить коммиты в GitHub и забрать оттуда | Когда задача попросит push |
| [3. Ветки и pull request](03-branches-and-pull-requests.md) | Ветка, pull request, разбор, слияние | Когда задача попросит pull request |

Термины остаются английскими (commit, push, pull, branch, merge): по ним ищут
в документации.

## Шпаргалка

Основные команды раздела и их кнопки в одном месте — чтобы вспомнить, не перечитывая
части. Кнопки — в панели Source Control (Система управления версиями) и в Status Bar
(Строка состояния) VS Code.

| Команда | Кнопка в Source Control | Что делает |
|---|---|---|
| `git status` | Список **Changes** | Какие файлы изменены и что войдёт в коммит |
| `git diff` | Нажать на файл в **Changes** | Изменения построчно |
| `git add .` | **+** у файла или у **Changes** | Отметить изменения для коммита |
| `git commit -m "сообщение"` | Поле **Message** и **Commit** | Сохранить отмеченное коммитом |
| `git log --oneline` | — | История коммитов, по строке на коммит |
| `git push` | **Sync Changes** | Отправить новые коммиты в GitHub |
| `git push --set-upstream origin имя` | **Publish Branch** | Первый раз отправить ветку (позже) |
| `git pull` | **⟳** у ветки в Status Bar | Забрать новые коммиты из GitHub |
| `git switch -c имя` | Ветка в Status Bar → **Create new branch...** | Создать ветку и перейти в неё (ветки — позже) |
| `git switch main` | Ветка в Status Bar → `main` | Вернуться в ветку `main` (позже) |
