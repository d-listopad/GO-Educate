# Git

Git — инструмент, которым программисты сохраняют историю своего кода и работают
над ним вместе. В курсе через git ты сдаёшь каждую задачу, поэтому знакомство
идёт постепенно: каждая часть нужна к определённому моменту.

| Часть | Что внутри | Когда нужна |
|---|---|---|
| [1. Репозиторий и коммит](01-repository-and-commit.md) | Что такое git, репозиторий, коммит; `git status`, `git add`, `git commit`, `git diff`, `git log` | Шаг 0, задача 1 |
| [2. GitHub: push и pull](02-github-push-pull.md) | Удалённый репозиторий, отправка коммитов в GitHub и получение их оттуда | Шаг 0, задача 1 |
| [3. Ветки и pull request](03-branches-and-pull-requests.md) | Ветка, pull request, разбор кода, слияние ветки | Шаг 1, задача 1 |

## Как здесь пишутся термины

Названия команд и основные термины остаются английскими: commit, push, pull, branch,
pull request, merge. По ним ищут в документации, и так их называют все программисты.
Русский жаргон из этих слов — «закоммитить», «запушить», «смержить» — в курсе
не используется: вместо него описывается действие. Не «запушить», а «отправить
коммиты в GitHub (push)».

## Шпаргалка

| Команда | Что делает |
|---|---|
| `git status` | Показывает, какие файлы изменены и что войдёт в следующий коммит |
| `git diff` | Показывает изменения построчно |
| `git add .` | Отмечает все изменения для следующего коммита |
| `git commit -m "сообщение"` | Сохраняет отмеченные изменения коммитом |
| `git log --oneline` | Показывает историю коммитов, по строке на коммит |
| `git push` | Отправляет новые коммиты в GitHub |
| `git pull` | Забирает новые коммиты из GitHub |
| `git switch -c имя` | Создаёт ветку и переходит в неё |
| `git switch main` | Возвращается в ветку `main` |
