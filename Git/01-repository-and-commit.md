# 1. Репозиторий и коммит

**Git** — программа, которая хранит историю проекта. Каждый сохранённый снимок
всех файлов с сообщением, что изменилось, автором и временем — **коммит** (commit).
Папка проекта вместе с историей коммитов — **репозиторий** (repository).

Репозиторий `pond` теперь в двух местах: на GitHub (шаг 0) и в Codespace — GitHub
скопировал его туда при создании Codespace. Коммиты сохраняются в Codespace;
как отправить их в GitHub — в [части 2](02-github-push-pull.md). Git в Codespace
уже настроен: имя и почта берутся из аккаунта GitHub.

| Команда | Что делает |
|---|---|
| `git status` | Какие файлы изменены и что войдёт в коммит |
| `git diff` | Изменения построчно |
| `git add .` | Отметить все изменения для коммита |
| `git commit -m "сообщение"` | Сохранить отмеченное коммитом |
| `git log --oneline` | История коммитов |

Все команды набирай в корне `pond`: строка приглашения кончается на `/workspaces/pond`.
Строка с `$` в блоках ниже — команда (без `$`), строки под ней — ответ.

## Три состояния изменения

1. **Изменено** — файл отредактирован.
2. **Отмечено** командой `git add` — изменение попадёт в следующий коммит. Место
   отмеченных изменений называется **индексом** (staging area): так можно положить
   в коммит не все изменённые файлы. В курсе почти всегда отмечаем всё: `git add .`,
   точка — «все изменения в текущей папке и глубже».
3. **Сохранено** командой `git commit`.

## `git status`

```
$ git status
On branch main
Your branch is up to date with 'origin/main'.

Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   main.go

no changes added to commit (use "git add" and/or "git commit -a")
```

- `On branch main` — ты в ветке `main`, основной ветке репозитория; что такое ветки,
  разберём позже.
- `up to date with 'origin/main'` — в GitHub те же коммиты, что у тебя (часть 2).
- `modified: main.go` — файл изменён, но не отмечен.
- Строки `(use …)` — подсказки git, выполнять не нужно.

Новые файлы стоят в списке `Untracked files` (в Explorer — буква **U**, шаг 1).
`nothing to commit, working tree clean` — всё сохранено.

## `git diff`

Строка с `+` добавлена, с `-` удалена, без знака — не менялась:

```
$ git diff
diff --git a/README.md b/README.md
index 39a1a10..7294eb9 100644
--- a/README.md
+++ b/README.md
@@ -1,3 +1,4 @@
 # pond
 
 «Пруд» — программа о жабках. Запуск: go run .
+Жабка квакает и здоровается.
```

Первые пять строк — какой файл и какое место в нём. `git diff` показывает только
неотмеченное: после `git add .` он молчит, поэтому смотри его до отметки — так
находится то, что в коммит попасть не должно. Если внизу терминала `:` — ответ
длинный и показан постранично: пробел листает, `q` — выход (Ctrl + C не помогает).

## `git add .` и `git commit`

```
$ git add .
$ git commit -m "В README описано, что умеет жабка"
[main b08c737] В README описано, что умеет жабка
 1 file changed, 1 insertion(+)
```

После `-m` в кавычках — **сообщение коммита** (commit message). `git add` ничего
не отвечает. `git commit` отвечает веткой, номером коммита (у тебя другой) и тем,
сколько строк изменилось; у новых файлов ещё строка `create mode 100644 имя` — число
пропусти.

## `git log --oneline`

```
$ git log --oneline
3fbd5aa (HEAD -> main) В README описано, что умеет жабка
127484c (origin/main, origin/HEAD) Жабка квакает
384560f Create devcontainer.json
8d339cd Initial commit
```

Слева — номер коммита, справа — сообщение, новые сверху. Два нижних коммита сделал
GitHub в шаге 0. `HEAD -> main` — где ты сейчас, `origin/main` — что уже есть
в GitHub: этот коммит ещё не отправлен.

## Сообщение коммита

Говорит, что теперь умеет программа или что исправлено: его читают, когда ищут,
где что менялось.

| Хорошо | Плохо |
|---|---|
| `Жабка представляется по имени` | `задание 1` |
| `Исправлено приветствие` | `правки`, `fix` |

Одна задача — один коммит; исправление после разбора — отдельный коммит.

Панель **Source Control** не используем (шаг 1): в терминале видно, что происходит.
Её кнопки **Commit** и **Sync Changes** — то же, что `git commit` и `git push`.

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| `nothing added to commit but untracked files present` | Новые файлы не отмечены: `git add .` и снова коммит |
| Опечатка в сообщении коммита | Оставить, историю не исправляем |
| После `git commit` без `-m` открылась вкладка `COMMIT_EDITMSG` | Напиши сообщение в первой строке, Cmd + S, закрой вкладку. Закрыть пустой — коммит отменится |
| Внизу терминала `:`, он не отвечает | Постраничный просмотр: клавиша `q` |
| Нужно вернуть файл к последнему коммиту | `git restore имя-файла`. Изменения пропадут безвозвратно |
