# 1. Репозиторий и коммит

## Зачем это нужно

Код меняется постоянно: добавляется новое, исправляются ошибки, что-то ломается.
Без истории изменений нельзя ответить на простые вопросы: что было вчера, когда
появилась ошибка, что именно изменилось. Копировать папку проекта перед каждой
правкой неудобно и быстро превращается в хаос.

Удобно представить альбом снимков: время от времени проект фотографируется целиком,
к снимку подписывается, что изменилось, и к любому снимку можно вернуться.

**Git** — программа, которая ведёт такую историю. Каждый сохранённый снимок называется
**коммитом** (commit): это состояние всех файлов проекта в определённый момент
вместе с сообщением, что изменилось, автором и временем. Папка проекта вместе
с историей коммитов называется **репозиторием** (repository).

В шаге 0 репозиторием мы назвали папку на GitHub. Когда создавался Codespace, GitHub
скопировал в него весь репозиторий вместе с историей. Теперь их два: на GitHub
и в Codespace. Коммиты из этой части сохраняются в Codespace; как отправить их
на GitHub — часть 2.

В Codespaces git уже установлен и настроен: имя и почта для коммитов берутся
из твоего аккаунта GitHub.

## Три состояния изменений

Изменение в файле проходит три стадии:

1. **Изменено.** Файл отредактирован, но git его пока только видит.
2. **Отмечено для коммита.** Командой `git add` изменение отобрано в следующий коммит.
   Это место называется **индексом** (staging area).
3. **Сохранено в коммите.** Командой `git commit` отмеченные изменения записаны
   в историю.

Зачем отдельный шаг отметки: иногда изменено несколько файлов, а в коммит должны
попасть не все. В курсе почти всегда в коммит идёт всё: `git add .`, где точка
означает «все изменения в текущей папке и глубже».

## Команды

### `git status` — что изменилось

Показывает, в каком состоянии файлы. Её стоит выполнять перед каждым коммитом.
Здесь и дальше строка с `$` — команда, которую ты набираешь (без `$`), строки под
ней — ответ.

```
$ git status
On branch main
Your branch is up to date with 'origin/main'.

Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   main.go

no changes added to commit (use "git add" and/or "git commit -a")
```

- `On branch main` — ты в ветке `main` (ветки — часть 3).
- `Your branch is up to date with 'origin/main'` — в GitHub те же коммиты, что
  у тебя (часть 2).
- `modified: main.go` — файл изменён, но ещё не отмечен для коммита.
- Строки в скобках `(use …)` — подсказки git, выполнять их не нужно.

Новые файлы, которых git ещё не записывал, стоят в отдельном списке
`Untracked files` (буква **U** в Explorer, шаг 1); `git add .` отмечает и их. Если
менять нечего, git скажет `nothing to commit, working tree clean`: всё сохранено.

### `git diff` — что именно изменилось

Показывает изменения построчно. Строка с `+` в начале добавлена, с `-` — удалена,
без знака — осталась как была и показана для ориентира. Например, в `README.md`
дописали строку:

```
$ git diff
diff --git a/README.md b/README.md
index 39a1a10..7294eb9 100644
--- a/README.md
+++ b/README.md
@@ -1,3 +1,4 @@
 # pond
 
 «Пруд» — программа о жабках. Запуск: go run .
+Жабка квакает и здоровается.
```

Первые строки (`diff --git`, `index`, `---`, `+++`, `@@ … @@`) говорят, какой файл
и какое место в нём; смотри на строки с `+` и `-`. `git diff` показывает только
изменения, ещё не отмеченные `git add`: после `git add .` он ничего не выведет,
поэтому набирай его до отметки. Если ответ длиннее терминала, git показывает его
постранично и внизу ставит `:`. Листай пробелом, выход — клавиша `q` (Ctrl + C здесь
не помогает).

Перед коммитом полезно просмотреть `git diff`: часто так находится то, что в коммит
попасть не должно, например временная строка для проверки.

### `git add .` и `git commit -m "..."` — сохранить коммит

```
$ git add .
$ git commit -m "В README описано, что умеет жабка"
[main b08c737] В README описано, что умеет жабка
 1 file changed, 1 insertion(+)
```

После `-m` в кавычках пишется **сообщение коммита** (commit message). `git add`
ничего не отвечает. Ответ `git commit`: ветка, короткий номер коммита (у тебя другой)
и сообщение, ниже — сколько файлов и строк изменилось. Для новых файлов будут ещё
строки `create mode 100644 имя` — число пропусти.

### `git log --oneline` — история

```
$ git log --oneline
3fbd5aa (HEAD -> main) В README описано, что умеет жабка
127484c (origin/main, origin/HEAD) Жабка квакает
384560f Create devcontainer.json
8d339cd Initial commit
```

Слева — короткий идентификатор коммита, справа — его сообщение. Новые коммиты сверху.
Два нижних коммита сделал GitHub в шаге 0, когда ты создавала репозиторий
и `devcontainer.json`. В скобках — где ты сейчас (`HEAD -> main`: последний коммит
ветки `main`) и что уже есть в GitHub (`origin/main`). Здесь новый коммит ещё
не отправлен: после `git push` (часть 2) `origin/main` встанет рядом с ним.

## Как писать сообщение коммита

Сообщение читают через месяц, когда ищут, где что изменилось. Поэтому оно говорит,
что теперь умеет программа или что исправлено:

| Хорошо | Плохо |
|---|---|
| `Жабка представляется по имени` | `задание 1` |
| `Новая жабка начинает без имени и голодной` | `правки` |
| `Исправлено приветствие` | `fix` |

Одна задача курса — один коммит. Если по ходу разбора что-то исправляется,
исправление — отдельный коммит со своим сообщением.

## Панель Source Control

В курсе git — командами в терминале, панель **Source Control** не используем (шаг 1):
в терминале видно, что именно происходит, а в сообщениях об ошибках и в документации
используются именно команды. Если в чужой инструкции увидишь кнопки **Commit**
и **Sync Changes** — это то же, что `git commit` и `git push`.

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| `nothing added to commit but untracked files present` | Файлы новые, их не отметили. Выполнить `git add .` и повторить коммит |
| `nothing to commit, working tree clean` | Изменений нет: всё уже сохранено |
| В сообщении коммита опечатка | Не страшно, оставить. Исправлять историю в курсе не нужно |
| Набрала `git commit` без `-m`, и в редакторе открылась вкладка `COMMIT_EDITMSG` | В первой строке напиши сообщение, нажми Cmd + S и закрой вкладку крестиком — коммит сохранится. Если закрыть вкладку, ничего не написав, коммит отменится |
| Внизу терминала `:` и он не отвечает | Это постраничный просмотр `git diff` или `git log`: выход — клавиша `q` |
| Изменения в файле не нужны, хочется вернуть как было в последнем коммите | `git restore имя-файла`. Осторожно: изменения пропадут безвозвратно |
