# 1. Репозиторий и коммит

## Зачем это нужно

Код меняется постоянно: добавляется новое, исправляются ошибки, что-то ломается.
Без истории изменений нельзя ответить на простые вопросы: что было вчера, когда
появилась ошибка, что именно изменилось. Копировать папку проекта перед каждой
правкой неудобно и быстро превращается в хаос.

Удобно представить альбом снимков: время от времени проект фотографируется целиком,
к снимку подписывается, что изменилось, и к любому снимку можно вернуться.

**Git** — программа, которая ведёт такую историю. Каждый сохранённый снимок называется
**коммитом** (commit): это состояние всех файлов проекта в определённый момент
вместе с сообщением, что изменилось, автором и временем. Папка проекта вместе
с историей коммитов называется **репозиторием** (repository).

В Codespaces git уже установлен и настроен: имя и почта для коммитов берутся
из твоего аккаунта GitHub.

## Три состояния изменений

Изменение в файле проходит три стадии:

1. **Изменено.** Файл отредактирован, но git его пока только видит.
2. **Отмечено для коммита.** Командой `git add` изменение отобрано в следующий коммит.
   Это место называется **индексом** (staging area).
3. **Сохранено в коммите.** Командой `git commit` отмеченные изменения записаны
   в историю.

Зачем отдельный шаг отметки: иногда изменено несколько файлов, а в коммит должны
попасть не все. В курсе почти всегда в коммит идёт всё: `git add .`, где точка
означает «все изменения в текущей папке и глубже».

## Команды

### `git status` — что изменилось

Показывает, в каком состоянии файлы. Её стоит выполнять перед каждым коммитом.

```
$ git status
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   main.go
```

`modified: main.go` — файл изменён, но ещё не отмечен для коммита. Если менять
нечего, git скажет `nothing to commit, working tree clean`: всё сохранено.

### `git diff` — что именно изменилось

Показывает изменения построчно. Строка с `+` в начале добавлена, с `-` — удалена.

```
$ git diff
--- a/main.go
+++ b/main.go
@@ -6,4 +6,5 @@ func main() {
 	fmt.Println("Ква!")
+	fmt.Println(strings.ToUpper("Ква!"))
 }
```

Перед коммитом полезно просмотреть `git diff`: часто так находится то, что в коммит
попасть не должно, например временная строка для проверки.

### `git add .` и `git commit -m "..."` — сохранить коммит

```sh
git add .
git commit -m "Жабка квакает громко"
```

После `-m` в кавычках пишется **сообщение коммита** (commit message).

### `git log --oneline` — история

```
$ git log --oneline
a1b2c3d Жабка квакает громко
9f8e7d6 Жабка квакает
```

Слева — короткий идентификатор коммита, справа — его сообщение. Новые коммиты сверху.

## Как писать сообщение коммита

Сообщение читают через месяц, когда ищут, где что изменилось. Поэтому оно говорит,
что теперь умеет программа или что исправлено:

| Хорошо | Плохо |
|---|---|
| `Жабка представляется по имени` | `задание 1` |
| `Новая жабка начинает без имени и голодной` | `правки` |
| `Исправлено громкое кваканье` | `fix` |

Одна задача курса — один коммит. Если по ходу разбора что-то исправляется,
исправление — отдельный коммит со своим сообщением.

## То же без терминала

В Codespaces всё это можно сделать мышью: иконка **Source Control** слева
(три кружка с линиями). Там список изменённых файлов, по клику на файл — его
изменения, как в `git diff`. Поле **Message** — сообщение коммита, кнопка
**Commit** — коммит. Если VS Code спросит, отметить ли все изменения автоматически,
отвечай **Yes**: это то же, что `git add .`.

Команды в терминале стоит знать всё равно: в сообщениях об ошибках и в документации
используются именно они.

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| `nothing added to commit but untracked files present` | Файлы новые, их не отметили. Выполнить `git add .` и повторить коммит |
| `nothing to commit, working tree clean` | Изменений нет: всё уже сохранено |
| В сообщении коммита опечатка | Не страшно, оставить. Исправлять историю в курсе не нужно |
| Изменения в файле не нужны, хочется вернуть как было в последнем коммите | `git restore имя-файла`. Осторожно: изменения пропадут безвозвратно |
